StuntKey

Your AI coding agent uses your API keys without seeing them. The real key stays in your computer’s keychain; the agent only ever gets a stand-in — a stunt double.

pip install stuntkey
stuntkey get openai        # opens the key page, you click Copy, it tests and stores the key
stuntkey install           # connects Claude Code, Cursor, VS Code, Codex and more
stuntkey proxy -- python app.py   # your code runs unchanged; it never holds the real key

What it does

  • Keys stay out of the AI’s sight. Stored in the Windows, Mac or Linux keychain. The agent asks StuntKey to make a call, or talks to a local stand-in address, and StuntKey adds the key on the way out.
  • Blocks the sneaky routes. Stops agents dumping environment variables, reading private keys and credential files, and hides keys that show up in command output before the AI sees them.
  • Spending caps per key. Set a daily limit on calls and tokens for each key, plus a one-command stop switch.
  • Leaked a key? stuntkey panic openai walks you through cancelling it, making a new one and finding every copy of the old one.
  • Finds keys already lying around in your project, your AI tools’ MCP settings and your git history — and moves them into the keychain.
  • Checks your website for keys shipped to every visitor. (Also available as our free website key checker.)

Tested in the open

We publish the Agent Leak Benchmark: 61 ways an AI agent can expose a key. With no protection, 54 of them leak. With StuntKey’s full setup, 58 are stopped (46 blocked, 12 hidden) and 3 still get through — we list which and why. Run it yourself: python -m leakbench in the repository.

What it does not do

  • It reduces risk; it does not remove it. It is beta and has not had an independent security review yet.
  • It cannot stop an agent misusing a key it is allowed to use — give each key only the permissions it needs.
  • It does not protect against malware running as you. Full limits: threat model.
